# AI 分析摘要需求

日期：2026-10-22。状态：**首版已实现并通过本地受控验证，真实模型、远端CI及部署尚未验证**。
实际行为与证据见 [IMPL-AI分析摘要.md](IMPL-AI分析摘要.md)；下文保留原需求与验收基线。

本轮承接已实现的运营分析闭环，为数据概览增加「让助手解读」入口。
优先完成一个可核对的场景：已应用筛选 → 获取同口径报告 → 阅读解读与依据 → 查看对应订单。
本文是下一轮实施基线；当前版本的发布阻塞仍须先收口，不能将本规划视为已交付。

## 1. 用户与目标

主要用户是有分析和 AI 使用权限的运营人员、分析人员。
用户已经可以查看周期比较、分布图和订单明细，但仍需自己组织指标含义与核查步骤。
本功能帮助用户快速阅读已有统计，并把说明和可核对的数据、订单入口放在一起。

典型场景：选择投标订单、一个日期区间及地区，应用查询后点击「让助手解读」。
系统展示本期与比较期的订单数、担保金额、保费变化，说明本期分类分布及数据局限，
用户从依据卡进入同条件订单列表。所有统计以服务端报告为准。

首版成功标准：用户无需重复输入日期和地区；摘要与其引用报告的指标一致；
每项观察都能定位到依据；筛选变化或请求失败不会留下看似有效的旧解读。

## 2. 已核对的实现基础

| 机构排行按机构与地区组合统计 | 依据与订单链接同时携带机构 ID、地区编码，不能仅按机构跳转 |
| 页面已有查询、导出和下钻；`analysisNavigation.ts` 校验并恢复路由参数 | 复用路由及精确地区下钻规则，不根据显示名称猜 ID |
| 模型配置、超时与 AI 运行观测已存在 | 复用相应基础设施；实施时核对哪些指标采集器可供独立请求调用 |

## 3. 首版范围

### 必须交付

- AS-01：分析页「让助手解读」按钮与页内结果面板，带入已应用查询条件。
- AS-02：服务端重新获取报告，返回确定性指标与来源元数据，再基于该报告生成简短说明。
- AS-03：展示总体变化、本期分布、数据局限和建议核查入口，每项观察关联依据。
- AS-04：依据卡支持查看对应订单，保留分析条件与返回路径。
- AS-05：覆盖权限、数据变化、失败降级、重复点击及过期结果处理。
- AS-06：确定性服务端测试、关键浏览器回归、受控模型评测及交付记录。

### 首版不包含

自由追问、多轮上下文、写操作、自动处置、主动通知、AI 报告文件导出、知识检索、
新增 MCP 工具、向量库、多模型路由和长期记忆。
不做地区/险种/机构的跨期贡献分析，不做风险评级、业务归因或预测。
首版结果停留在当前分析页，不写入全局聊天历史；后续若接入 Copilot，另行定义会话与数据快照的生命周期。

## 4. 页面行为

### 4.1 入口与状态

- 按钮放在当前筛选摘要附近；未加载报告、查询中或当前查询失败时不可点击。
- 请求只读取成功应用的服务端归一条件，不能读取尚未提交的表单值。表单有未应用修改时提示「请先查询后解读」，并禁用生成。
- 点击后在当前页展开结果面板；顺序为筛选与生成时间、确定性指标、解读、依据与订单入口。
- 生成期间显示状态，禁用重复生成；完成后提供「重新生成」，每次点击明确发起一次新请求。
- 页面初次加载、展开旧面板和改变筛选均不自动调用模型；不自动重试模型请求。
- 本期订单数为零时直接返回服务端无数据说明，不调用模型；仍如实展示比较期和完整性。

### 4.2 数据与旧结果

- 页面向服务端传查询条件及当前报告摘要指纹，不提交可信统计值。指纹由服务端报告响应提供，排除生成时间等易变字段，覆盖报告内容和归一条件。
- 服务端重新查询，生成本次报告指纹。若与页面报告不同，返回 `REPORT_CHANGED` 和新报告，不调用模型。
  页面用新报告刷新图表与摘要，清除旧解读，提示「数据已更新，请重新解读」。
- 报告查询事务在模型请求前结束，模型等待期间不得持有数据库事务或连接。
- 生成期间应用其他筛选、离页或退出登录时，前端取消等待并使本次请求标识失效；迟到响应不能覆盖新页面。
  客户端取消不保证上游立即停止或免除已产生费用，服务端仍受超时和并发限制约束。
- 重新生成时旧结果标记为已被替代；新请求失败后展示明确失败态，不把旧说明显示为本次成功结果。
- 首版不持久化结果；刷新后保留既有筛选路由，解读需用户重新触发。数据时间显示 Asia/Shanghai。

### 4.3 输出内容

| 区域 | 必需内容 |
|---|---|
| 分析范围 | 订单类型、实际日期、地区/机构、比较期、报告生成时间 |
| 指标事实 | 三项指标的本期、上期、绝对变化、变化率或新增/无变化；来自服务端 |
| 总体观察 | 解释已发生的总体变化；没有达到变化提示条件时不擅自升级为异常 |
| 本期分布 | 最多三条有依据的分布观察；标明 Top N 或实际返回范围 |
| 数据局限 | 比较数据可能不完整、无数据、缺少分类上期数据等适用说明 |
| 建议核查 | 查看本期订单、查看比较期订单、查看某个已返回分类的订单 |

说明保持简短，目标为 3–5 条观察，避免复述所有图表。全库概览不进入当前筛选解读。
例如固定夹具中本期80笔、上期100笔：指标卡显示减少20笔、下降20%；
解释只能说明订单量下降。若本期A地区排名第一，只能描述其本期分布，不能说A地区导致下降。

## 5. 统计与模型边界

- 订单类型仅 TENDER / PERFORMANCE；日期采用申请日期、含起止日、1–366天；比较期为紧邻的前一等长周期。
- 地区、机构及粒度按现有服务归一。页面必须先有明确日期，解读接口不接受缺省日期后自行换成另一时间窗口。
- 金额单位与现有页面一致；变化率、新增、无变化与完整性全部直接使用服务端字段，不让模型重算。
- 本期分布不提供跨期归因证据；不能使用“导致”“主要拖累”“贡献了下降”等因果或贡献表述。
- Top N 合计不代表全量，险种图的可视占比也不能当作全库占比。首版不新增占比或分类变化率指标。
- 模型只获得服务端构造的有限聚合事实及证据 ID，不发送订单明细、企业联系人、用户信息或聊天历史。
  趋势与分类事实按稳定排序设有上限；超限在服务端裁剪并记录范围，不能静默截断成完整报告。
- 模型无工具回调权限，不开放任意 SQL、URL 或写操作。分类名称作为不可信数据处理，不能改变系统指令。
- 数值、单位、名称、来源卡和订单链接由服务端事实及前端组件呈现；模型不生成可执行链接或 HTML。
- 解读采用结构化返回，每条说明必须引用有效 `evidenceIds`。服务端校验结构、长度、证据存在性；
  数字事实采用服务端模板呈现，模型文本不得另行写入未校验数值。校验失败直接降级，不自动二次调用。
- 引用存在不等于推理正确。无依据归因、夸大与提示注入还须通过语义评测验证；不能声称结构校验保证任意模型文本正确。

## 6. 接口与实现约束（建议契约）

建议新增 `POST /api/ai/analysis-summary`，返回普通 JSON。首版等待完整响应，便于在展示前校验；不增加 SSE 协议。

| 部分 | 内容 |
|---|---|
| 请求 | `criteria`：orderType/startDate/endDate/regionCode/orgId/granularity；`reportFingerprint`：页面当前服务端指纹 |
| 成功 | `status=GENERATED`、`report`、`reportFingerprint`、`generatedAt`、确定性事实、`observations[{text,evidenceIds}]`、`evidence` |
| 无数据 | `status=NO_DATA`、同口径报告、服务端说明；模型调用次数为0 |
| 数据更新 | HTTP 409、业务码 `REPORT_CHANGED`、新报告与指纹；模型调用次数为0 |
| 模型失败 | `status=FACTS_ONLY`、同口径报告及事实、可读失败原因与traceId；不返回伪造说明 |
| 无权限/参数错误/限流/统计失败 | 按现有异常响应规范返回，模型调用次数为0；统计失败不能包装为无数据 |

`evidence` 由服务端生成，含 ID、类型、对应事实、受控下钻参数；不接收客户端伪造来源。
总体依据有本期/比较期入口，分类依据只提供本期入口。订单类型及合法 ID、精确地区规则由既有导航函数处理。
如果页面展示后数据继续改变，订单列表显示当时查询结果；提示统计生成时间，不承诺历史订单快照可重放。

实现位于 `guarantee-ai`，调用其已依赖的 `guarantee-analysis` 服务，保持模块单向依赖。
复用模型配置与请求预算，使用独立、随应用版本管理的解读模板；不应用管理员的自由业务补充，
不修改聊天候选评测或当前发布版本。解读模板升级须更新本功能测试集与模板版本。

首版不新增业务表、不存储完整结果，不引入消息队列或后台任务。
报告响应增加指纹为兼容性新增字段，页面、导出与解读继续共用统计真源。

## 7. 权限、费用与观测

- 生成同时要求 `analysis:overview:view` 与 `ai:chat`；前端显隐与后端鉴权一致，不以角色名硬编码。
  缺任一权限时不查询统计、不调用模型；本轮不新增权限码或默认角色授权。
- 「查看订单」还要求对应的 `order:tender:view` 或 `order:performance:view`；无权限隐藏入口，订单接口独立校验。
- 复用现有分析数据可见口径。本项目未实现用户机构行级隔离，不将机构筛选或本功能描述成租户隔离。
- 同一用户最多一个解读请求在执行；服务端设有界全局并发，超限快速拒绝，不排无限队列。
  模型阶段总超时不超过60秒，配置更短时遵循更短值；无自动重试和自动生成，输出预算受现有配置限制。
- 复用现有AI调用记录/指标能力，记录场景、用户、traceId、报告指纹、模板版本、模型/配置版本、耗时、状态、失败原因和可获得的token用量。
  不把独立解读伪造成正常会话或工具调用；现有指标有会话外键限制时补场景日志适配，不创建虚假会话。
- 日志不记录密钥、完整输入报告或模型全文；不得因观测失败向用户展示伪造成功。

## 8. 验收标准

| 编号 | 可验证结果 |
|---|---|
| AC-AS-01 | 仅用已应用条件；未提交表单修改时不能生成；明确显示实际日期、比较期、筛选和生成时间 |
| AC-AS-02 | 两类订单的指标事实与同一服务端报告完全一致；客户端伪造统计、证据或超范围条件均不能成为模型输入 |
| AC-AS-03 | 覆盖零基数、两期为零、仅本期为零、比较不完整及阈值边界；无数据不调用模型，不完整条件不生成异常断言 |
| AC-AS-04 | 地区Top 10、机构与地区组合、险种返回范围有标识；不声称分类导致总体变化；每条观察有有效依据 |
| AC-AS-05 | 本期/比较期及三类分类入口与订单筛选一致；精确地区、组合机构条件、刷新及返回行为正确；无明细权限不可绕过 |
| AC-AS-06 | 缺任一生成权限、非法日期/ID/指纹、过载均明确拒绝；统计或模型调用次数符合第6、7节约定 |
| AC-AS-07 | 数据变更触发REPORT_CHANGED且不调用模型；刷新图表后由用户重试；切换筛选、离页、取消后的旧响应不污染结果 |
| AC-AS-08 | 缺模型密钥、超时、上游异常、无效结构、无效引用与未校验数值均降级为事实；页面不把降级标成AI生成成功 |
| AC-AS-09 | 受控模型验证提示注入、伪造链接、无依据因果与Top N误用；越界内容被拦截或由语义评测判失败，不能静默通过 |
| AC-AS-10 | traceId可关联请求与场景日志；调用次数、超时、并发和预算可核对；失败和取消状态如实记录 |
| AC-AS-11 | 相关单测、真库统计/权限集成、前端类型及构建、浏览器流程、SSOT与全量verify通过；远端CI另列证据 |
| AC-AS-12 | 在固定15万订单基线上分别记录统计、模型和端到端耗时；20次受控模型运行端到端p95目标≤3秒；真实模型延迟单列，不用受控值宣称真实性能 |

确定性测试使用脚本模型，不调用付费接口；真实模型语义评测须单列模型版本、模板版本、输入及结果。
未获得模型调用条件时标注「真实模型尚未验证」，不能以受控测试代替真实效果验收。
至少覆盖：正常下降/上升、无变化、新增、无订单、数据覆盖不完整、Top N、组合机构、
恶意分类名称、诱导归因、数值篡改、旧请求迟到、权限缺失与模型失败。
