# 运营分析闭环迭代计划

日期：2026-10-21。状态：**M1/M2 已实施并验证；M3 已接入回归，整体发布验收仍受一项既有知识条目冲突阻塞**。
实际结果见 [IMPL-运营分析闭环.md](IMPL-运营分析闭环.md)，本文其余章节保留原规划和验收基线。

## 1. 目标与范围

让运营人员完成「发现周期变化 → 查看对应订单 → 导出分析摘要」的闭环。
本轮优先复用既有分析、订单与权限体系；交付分为三个可独立验收的里程碑。
本文中的接口名、阈值和任务拆分为实施基线，性能目标为待实测目标。

典型场景：选择投标订单与一个日期区间，看到订单数相较前一等长周期下降，
查看地区分布并进入该地区的订单列表，最后导出带日期、筛选条件和比较口径的摘要。
页面只描述观察到的变化，不自动断言变化原因或业务风险。

本轮不含：订单审批/出函流程、主动消息通知、自动处置、明细批量导出、
AI 自动撰写报告、新增 MCP 工具、向量数据库、多模型路由、长期记忆。

## 2. 已核对的实现基础

## 3. M1：统计口径与周期变化（预计 3–4 个工作日）

### 任务

- OA-01：核对分析与订单 Mapper 的日期、地区匹配、逻辑删除、数据权限、JOIN 去重规则，建立可对照的夹具。
- OA-02：新增只读比较接口，建议 `GET /api/analysis/order-comparison`；通过 Service 共用汇总逻辑。
- OA-03：分析页补当前筛选摘要、比较区间与变化提示；全库概览显式标注为全库口径。
- OA-04：补计算边界与真实数据库聚合对照测试。

### 计算与展示约定

- 统计日期统一为申请日期，起止日期均包含；类型首轮仅 TENDER/PERFORMANCE，新比较接口对其他值报参数错误。
- 默认区间以数据覆盖结束日为锚点，向前取最多 30 天并展示实际日期，避免演示数据陈旧时页面默认全空。
- 用户可选 1–366 天；比较周期紧邻当前周期之前、天数相同。前端回显服务端归一后的条件。
- 指标为订单数、担保金额、保费金额；返回本期值、上期值、绝对变化、变化率与比较状态。
- 上期大于零：变化率 = (本期−上期)/上期 × 100%，服务端十进制计算、展示两位小数。
- 上期为零且本期为正：显示“新增”，变化率为空；两期为零显示“无变化”；本期为零且上期为正为 −100%。
- 比较区间越出已知数据覆盖范围时，标注“对比数据可能不完整”，不生成变化提醒；无订单不等同于断言数据缺失。
- 首版提醒仅针对订单数：上期至少 20 笔且变化率绝对值至少 30%；使用未舍入数值判断，常量集中定义并测试边界。
- 金额只展示变化；提醒称“变化提示”，不称风控结论，不根据统计相关性推断原因。

### 验收

- AC-OA-01：上述零基数、阈值边界、跨月/闰年、空数据、非法日期均有明确结果；非法请求不查询全库。
- AC-OA-02：两类订单在相同筛选下的比较汇总分别与独立 SQL 对照一致；金额与日期口径可核对。
- AC-OA-03：筛选变化后摘要与图表使用同一已应用条件；慢请求不得覆盖更新后的筛选结果。
- AC-OA-04：比较接口遵守现有服务端数据可见范围；直接请求不能绕过权限。现有权限码不足时先补最小权限及角色映射。

## 4. M2：图表下钻与摘要导出（预计 3–4 个工作日，依赖 M1）

### 任务

- OA-05：地区、险种、机构图表增加“查看订单”；以原始业务标识传参，禁止以显示名称反查或按数组序号猜测。
- OA-06：`OrderTable.vue` 接收路由参数、回显筛选；进入另一类订单时重新应用条件与分页，支持刷新及返回分析页。
- OA-07：增加“导出分析摘要 CSV”，首版导出服务端生成的聚合结果，不导出订单明细。
- OA-08：补下钻对照、导出权限及文件内容验证。

### 行为约定

- 下钻保留订单类型、日期、地区、机构，并合并点击维度；同维度点击值替换当前该维度条件，重置分页。
- Top N 图表只代表已返回分类；标明 Top N，不将其合计冒充全量。未知/空维度不能生成无条件跳转。
- 刷新保留筛选，返回分析页恢复已应用筛选；用户手工查询后 URL 与页面条件保持一致。
- 新导出接口建议 `GET /api/analysis/order-report/export`，复用 M1 与既有聚合 Service，不引入订单模块对分析模块的反向依赖。
- 导出含生成时间（Asia/Shanghai）、本期/比较期、筛选条件、统计单位、三项指标及地区/险种/机构表。
- 分布遵循页面相同的 Top N，文件中标出限额与全量总数。导出重新查询，明确标注“导出时查询结果”；静态测试数据下应与页面一致。
- CSV 使用 UTF-8 BOM、正确处理引号/换行，并将可被表格软件解释为公式的文本安全输出；不增加 XLSX 依赖。
- 新增独立权限 `analysis:export`，初始仅 ADMIN/ANALYST；后端强制校验，前端按权限显示入口。
- 权限同步到集中常量、目录、种子、存量幂等迁移与角色配置，记录导出动作、条件、结果条数及 traceId，不记录完整文件内容。

### 验收

- AC-OA-05：投标/履约 × 地区/险种/机构六条路径，下钻列表 total 等于对应分组订单数；保留全部适用条件。
- AC-OA-06：新页进入、路由变化、刷新、返回、重置均不残留上一条件；非法参数显示错误且不回退成全量查询。
- AC-OA-07：导出指标与独立 SQL 一致，日期、单位、Top N 标识齐全；中文、引号、换行及公式型文本样例通过验证。
- AC-OA-08：无导出权限时直接请求被服务端拒绝且无文件内容；导出与下钻不会扩大用户数据范围。

## 5. M3：关键流程回归与发布收口（预计 2–3 个工作日，依赖 M2）

- OA-09：建立 Playwright 浏览器回归入口，覆盖登录、权限入口、周期比较、图表下钻、摘要下载，以及既有 AI 提案确认流程。
- OA-10：确定性浏览器流程纳入 CI，失败保留截图/trace；AI 流程使用受控模型或既有确定性测试设施，不依赖付费模型在线结果。
- OA-11：在固定约 15 万订单基线记录比较/导出耗时与查询计划，再按实测决定是否加索引。
- OA-12：更新 API 文档、演示步骤及与本轮直接相关的过时状态，记录发布验收结果。

### 验收

- AC-OA-09：浏览器用例可独立重复运行，不依赖执行顺序或污染共享演示数据；无权限用例同时检查服务端拒绝。
- AC-OA-10：本机 Maven 使用 `scripts/mvn-locked.ps1`；相关单测/IT、前端类型与构建、SSOT 检查及浏览器流程通过。
- AC-OA-11：AI 提案链路未改动时使用确定性回归；若改动提示词或工具链，补确定性集及拒答多轮/真机验证，缺凭证标记未验证。
- AC-OA-12：性能目标为本机相同配置、单用户、预热后 20 次请求：比较接口 p95 ≤ 2s，摘要导出 p95 ≤ 5s；超标先分析查询，不据此宣称生产容量。
