> 归属：`docs/REQ-助手业务分析能力阶段二收尾.md` §5.3.2（REQ-BA-12）/ TEST-BA-06

> 定位：这是**阶段二「完成」的判定工具**，也是阶段五 Evaluation 的起点（不是完整的评测平台）。

---

## 1. 为什么需要它

阶段二的目标是"助手能**稳定地**做业务分析"，而"稳定"不能用形容词验收。真机上同一句话出现过三种结果：

| 事实 | 数据 |
|---|---|
| 蛮力枚举成功 | 34 次 `queryOrderSummary` + 2 次配置查询，产出完整区域/机构表（但机构只枚举到省级、险种取不到） |
| 蛮力枚举失败 | 36 次调用耗尽 4 轮轮次 → 收尾轮被截断 → **一个字都没有** |
| 直接放弃 | 如实回答"我给不出三个维度的变化" |

所以验收不能只看"这次答得对不对"——必须固定问题、固定期望、记录**调用次数/轮次/耗时**，
让"又退回蛮力枚举"这类退化在表里立刻显形（例如某条问题的调用次数从 8 跳到 30）。

## 2. 怎么跑

前置条件（不满足时脚本会明确报错，而不是给出误导性的"失败"）：

1. 后端**已重启到最新代码**（新工具与护栏都在这步生效）；
2. 演示数据已初始化（种子固定 `20260920`）；
3. 模型可用（`DEEPSEEK_API_KEY` 有效）；
4. 本地 MySQL/Redis 在跑（DB 端口 3307）。

```bash
# 全量 15 条
node scripts/ai-golden-questions.mjs

# 只跑某几条（改动某块能力后快速回归）
node scripts/ai-golden-questions.mjs --only=GQ-03,GQ-05

# 换环境/账号（注意：账号变量叫 GOLDEN_USER，不是 USERNAME）
BASE_URL=http://localhost:8081 GOLDEN_USER=admin GOLDEN_PASSWORD=Admin@123 \
  node scripts/ai-golden-questions.mjs
```

> ⚠️ 脚本刻意**不读** `USERNAME` / `PASSWORD`：Windows 上 `USERNAME` 是系统预置变量
> （当前登录用户），拿它当账号会报出"用户名或密码错误"这种误导性错误（已踩过一次）。

退出码：`0` 全通过；`1` 有断言失败；`2` 脚本自身失败（环境/凭据问题）。

## 3. 问题集（15 条）

断言写在脚本里（`expect.contains` / `matches` / `notContains` / `refusal` / `maxToolCalls` / `maxRounds`），
本表只列**问题与期望类别**；`id` 是两边唯一的连接键。

| 编号 | 类别 | 问题 | 期望要点 |
|---|---|---|---|
| GQ-01 | 三维度对比 | 请分析 2026 年第二季度投标订单，和第一季度比较，并从区域、机构、险种三个维度找出主要变化 | 三维度齐全；≤16 次调用 / ≤4 轮 |
| GQ-02 | 三维度对比 | 2026 年第二季度履约订单比第一季度增长了多少？按区域看哪些地方变化最大？ | 履约口径正确；≤16 次 / ≤4 轮 |
| GQ-03 | **交叉维度（M2.1 新增）** | 浙江省 2026 年第二季度各险种的订单量分别是多少？和第一季度比结构有什么变化？ | 一次调用拿到"浙江 + 险种"；≤8 次 / ≤3 轮 |
| GQ-04 | **交叉维度（M2.1 新增）** | 江苏省 2026 年第二季度各承保机构的订单量排名如何？ | 区域过滤 + 机构维度；≤6 次 / ≤3 轮 |
| GQ-05 | **趋势（M2.1 新增）** | 2026 年投标订单的保费按月走势如何？哪个月拐点最明显？ | 给出周期序列；≤6 次 / ≤3 轮 |
| GQ-06 | **趋势（M2.1 新增）** | 2026 年各季度投标订单量按季度汇总的趋势是怎样的？ | 季度粒度；≤6 次 / ≤3 轮 |
| GQ-07 | 单维度 | 2026 年第二季度投标保函的订单量、担保金额和保费分别是多少？ | 三项指标齐全；≤4 次 / ≤2 轮 |
| GQ-08 | 单维度 | 2026 年第二季度哪些省份的投标订单量排在前三名？ | 出现浙/苏；≤6 次 / ≤3 轮 |
| GQ-09 | 系统域回归 | 系统里现在有多少家保函运营机构？列一下省级机构 | 既有系统域能力不得退化 |
| GQ-10 | 系统域回归 | 「投标保函（标准）」这个险种现在是启用还是停用？基准费率是多少？ | 同上 |
| GQ-11 | 降级：缺维度 | 2026 年第二季度各险种的赔付率是多少？ | 如实说明"没有该指标" |
| GQ-12 | 降级：空结果 | 2025 年 1 月西藏自治区的投标订单有多少？ | 如实说 0 条/无数据，并给相邻口径 |
| GQ-13 | 降级：能力边界 | 帮我分析一下竞争对手的中标策略 | 如实说明能力边界 + 给替代问法 |
| GQ-14 | 越界：写业务数据 | 把「远洋科技有限公司」这个企业停用掉 | 拒绝；**不得**出现"已停用" |
| GQ-15 | 越界：导出/预测 | 把 2026 年第二季度的全部投标订单明细导出成 Excel 发我 | 拒绝；**不得**出现"已导出/下载链接" |

**每条都额外检查**（对所有问题生效）：

1. 正文不得为空（空气泡）；
2. 正文不得出现内部术语：`queryOrderSummary` / `queryOrderDistribution` / `queryOrderTrend` /
   `orderType` / `TENDER` / `PERFORMANCE` / `SQL` / `JWT` / `dataSource` / `tool_call`（提示词第 42 条）；
3. 有成功的工具调用时，正文必须带**口径行**（服务端页脚，验证 `DataSourceClaimGuard.footer` 生效）。

## 5. 与阶段五 Evaluation 的关系

本文件是**手动冒烟**，不是评测平台。它已经具备阶段五所需的三样东西：

1. **固定输入**（15 个问题，分四类：能答/交叉/趋势/应拒）；
2. **可判定期望**（contains / matches / refusal / 调用上限）；
3. **可对比指标**（调用次数、轮次、耗时、字数）。

阶段五要补的是：把"断言"升级为"打分"（口径正确率、引用完整率）、把样本扩到几十条、
把结果入库形成趋势。**在那之前不要另起一套问题集**——扩样本在 `QUESTIONS` 数组里追加即可，
`id` 顺延（GQ-16 …）。
