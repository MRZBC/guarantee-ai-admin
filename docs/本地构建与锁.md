# 本地构建与 maven 锁（`scripts/mvn-locked.ps1`）

> 一句话：**改代码后跑 Maven，一律走 `pwsh -File scripts/mvn-locked.ps1 …`**。
> 它做的事只有三件：取 `.agent/locks/maven.lock` → 原样跑 `mvn` → `finally` 释放锁。

## 1. 为什么要锁

本机所有阶段共用**同一个** MySQL(3307) 与 Redis(6379)。两个 `mvn` 并发跑时，IT 会互相踩夹具：

- 本轮真实事故：`LogicalDeleteWebIT` 因**两个构建共用一个数据库**而红，隔离重跑**全绿**——
  不是代码问题，是环境问题；却要靠人肉分辨，浪费一整轮排查。
- 更隐蔽的形态：两个构建各自启动 Spring 上下文、各自 `CREATE TABLE IF NOT EXISTS` / 播种 /
  删除夹具行，失败信息指向被测代码，实际是并发写库。

锁是最便宜的解法：**串行化本机的 Maven**，不改变任何测试语义。

## 2. 怎么用

```powershell
# 与 mvn 同形：除 5 个 -Lock* 控制参数外，其余参数原样转发
pwsh -File scripts/mvn-locked.ps1 -pl guarantee-common test
pwsh -File scripts/mvn-locked.ps1 -B verify
pwsh -File scripts/mvn-locked.ps1 -pl guarantee-web -am -DskipTests package

# 快速探测：有人持锁就立刻退出（不等待）
pwsh -File scripts/mvn-locked.ps1 -LockWaitMinutes 0 -v      # ⚠️ -v 见 §4

# 控制参数（都带 Lock 前缀，刻意避开 maven 的所有单字母开关）
#   -LockStaleMinutes 20   陈旧阈值：锁 age ≥ 20 分钟视为陈旧，**告警后抢占**
#   -LockWaitMinutes  20   未取到锁时的最长等待；超时**不跑 mvn**，退出码 3
#   -LockPollSeconds  60   轮询间隔
#   -LockOwner             写进锁的 owner（默认环境变量 DSH_AGENT_NAME）
#   -LockQuiet             只打印取锁/抢占/释放，不打印每次轮询
```

退出码：**`mvn` 的退出码原样透传**；`3` = 等待超时未取到锁（此时**没有**执行 mvn）；`4` = PATH 里找不到 `mvn`。

### 2.1 锁协议

`.agent/locks/maven.lock` 内容（与仓内其它 Agent 的约定一致）：

```
owner=<谁> time=<ISO8601> nonce=<随机串>
```

| 情况 | 行为 |
|---|---|
| 锁不存在 | 取锁：写入后**等 3 秒回读 nonce 自证**（避免两个进程同写的竞态） |
| 锁新鲜（age < `-LockStaleMinutes`） | 按 `-LockPollSeconds` 轮询等待，最多 `-LockWaitMinutes` |
| 锁**陈旧**（age ≥ 20 分钟，或 `time` 不可解析） | **打印告警后抢占**（陈旧锁多是上次进程被 kill 留下的，不抢占会永久卡住所有人） |
| 等待超时 | **不执行 mvn**，退出码 3 —— 绝不"没拿到锁也跑"，那正是事故成因 |
| 退出（正常/异常/Ctrl+C） | `finally` 释放；**只删自己写的那把**（回读 nonce 一致才删，不会误删别人的锁） |

事件流写 `.agent/locks/maven-lock.log`（取锁/抢占/执行/结束/释放，含时间戳），便于事后对账。

### 2.2 ⚠️ CI 内不需要

GitHub Actions 的 runner 之间**环境隔离**（每个 job 有自己的 MySQL/Redis service，见
`.github/workflows/ai-eval.yml` 的 `services:`），不存在共享夹具。因此 workflow 里
**照常直接 `mvn`**，不要包这一层（还会白拿一个锁文件、给日志添噪）。

```
# ① 正常跑完 → 释放
$ pwsh -File scripts/mvn-locked.ps1 -pl guarantee-common test
[mvn-locked] 已获得 maven 锁（owner=unknown）
[mvn-locked] 执行：mvn  -pl guarantee-common test
[INFO] Tests run: 7, Failures: 0, Errors: 0, Skipped: 0
[INFO] BUILD SUCCESS
[mvn-locked] mvn 结束：exit=0，耗时 6.7s
[mvn-locked] 已释放 maven 锁
          退出码=0；锁文件已删除

# ② 他人持新鲜锁 → 等待 → 超时（**没有**执行 mvn）
$ pwsh -File scripts/mvn-locked.ps1 -LockWaitMinutes 0 -LockPollSeconds 5 -v
[mvn-locked] 锁被 other-agent 持有（age=0.0 分钟，阈值 20 分钟）；等待已达上限 -LockWaitMinutes=0 → 不执行 mvn，退出码 3
          退出码=3；他人的锁文件**完好未动**（owner=other-agent）

# ③ 陈旧锁（25 分钟）→ 告警 + 抢占
$ pwsh -File scripts/mvn-locked.ps1 -v
[mvn-locked] ⚠️ 检测到陈旧锁并**抢占**：owner=ghost-agent age=25.0 分钟（阈值 20 分钟）…
[mvn-locked] 已（抢占后）获得 maven 锁
[mvn-locked] 已释放 maven 锁

# ④ 等待后拿到锁（他人 8 秒后释放）
[mvn-locked] 锁被 other-agent 持有（age=0.0 分钟，阈值 20 分钟）；5 秒后重试（等待上限 2 分钟）
[mvn-locked] 锁被 other-agent 持有（age=0.1 分钟，阈值 20 分钟）；5 秒后重试（等待上限 2 分钟）
[mvn-locked] 已获得 maven 锁（owner=unknown）
```

另外真机上还碰到过"抢锁竞争失败（3 秒内被别人覆盖），重试"→ 随后成功取锁：
这正是 3 秒回读自证在保护"两个进程同时看到空锁"的场景。

## 4. ⚠️ PowerShell 会吃掉部分 maven 开关（实测表）

本脚本用 `[CmdletBinding(PositionalBinding=$false)]` + `ValueFromRemainingArguments` 转发参数，
**绝大多数开关原样通过**；但 PowerShell 的**公共参数**与**前缀匹配**会截走下面几个：

| maven 开关 | 直接写 `-v` | 说明 |
|---|---|---|
| `-v`（version） | ❌ **被静默当成 `-Verbose`**（maven 收不到；脚本会打印告警） | 用逃生舱 |
| `-e`（errors） | ❌ 报错（`-e` 在 ErrorAction/ErrorVariable 间歧义） | 用逃生舱 |
| `-o`（offline） | ❌ 报错（`-o` 在 OutVariable/OutBuffer 间歧义） | 用逃生舱（且本项目**禁止** `mvn -o`） |
| `-P`（profile） | ❌ 报错（前缀匹配 `-PipelineVariable`） | 用逃生舱 |
| `-q -B -U -am -N -f -T -X -pl -D…` | ✅ 原样转发 | 直接写 |

**两个逃生舱（都实测有效）**：

```powershell
# A) 冒号语法（注意是 `-MvnArgs:'-v'` 而不是 `-MvnArgs '-v'`：
#    外层 pwsh 会把引号解析掉，到达脚本时变成无引号的 -v，照样被绑成 -Verbose）
pwsh -File scripts/mvn-locked.ps1 -MvnArgs:'-v'
pwsh -File scripts/mvn-locked.ps1 -MvnArgs:'-P prod test'

# B) 环境变量（**数据不走 argv**，任何 PowerShell 解析都吃不到它）
$env:MVN_LOCKED_ARGS = '-P prod -v'
pwsh -File scripts/mvn-locked.ps1
```

在 pwsh 会话内用 `&` 直接调脚本时，引号是有效的：`.\scripts\mvn-locked.ps1 -MvnArgs '-v'`。

## 5. 与其它运维约定的关系

- **不要**用 `-Dspring-boot.repackage.skip=true` 规避"jar 被占用"：它会把 fat jar 原地改写成
  thin jar（详见 `reports/README.md` 运维小节）。要起临时实例请用
  `scripts/run-local-classpath.ps1`（classpath 方式，不锁 fat jar）。
- 临时实例的端口纪律：**绝不用 8081**（那是用户自己的实例）。
