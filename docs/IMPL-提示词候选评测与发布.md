# 提示词候选评测与发布

日期：2026-10-21；第二批更新于2026-10-22。两批均已实现并完成相关本地验证，尚未部署。

## 行为与接口

编辑顺序：恢复已有草稿，否则读取当前生效正文（发布版或 jar 内置版）。打开页面不创建版本，保存草稿才写库。管理端读库失败明确报错；助手运行期仍保留 classpath 兜底。

| 方法与路径（前缀 `/api/ai/config`） | 权限 | 行为 |
|---|---|---|
| GET `/prompts/effective` | ai:config:view | source、versionNo、content、contentHash |
| POST `/prompts/evaluations` | ai:config:update | 接收 versionNo、contentHash；保存候选/基线快照，返回任务 |
| GET `/prompts/evaluations/{id}` | ai:config:view | 读取状态、逐题结果、配置快照和当前是否可发布 |
| GET `/prompts/{versionNo}/evaluation` | ai:config:view | 当前版本最近一次评测；从未评测为 null |
| POST `/prompts/publish` | ai:config:update | 必须携带 versionNo、contentHash、evaluationId |
| POST `/prompts/rollback` | ai:config:update | 原有 versionNo 请求；不重跑模型，事务切换与审计 |
| GET `/prompts/gate` | ai:config:view | 兼容旧客户端的提示视图；不再执行命令 |

发布不启动 Node、Maven 或模型请求，也不接受前端传入的“通过”标志。后端核对评测终态、目标版本、完整正文及哈希、配置/实现指纹、测试集版本和24小时有效期。发布、回滚、草稿分配和管理端配置修改共用控制行锁。归档旧版、发布新版、配置投影及审计都在同一短事务内，任一步失败整体回滚。发布审计追加 evaluationId。

## 候选行为评测的边界

`order-time-v1` 固定日期2026-10-21，包含未指定时间、上个月、全部历史、多轮补充“上个月”四种场景。每题运行候选版和提交时的生效版，展示回答及工具参数对比。

复用 AiChatService 的模型参数、TimeSemanticParser、BusinessAssistantPrompt 运行上下文和生产工具调用循环。工具定义来自正常注册表，回调替换成固定数据：日期工具返回固定日期，订单汇总返回37。其他工具不会执行真实业务逻辑。本入口不写入正常会话、消息、提案或业务表。结果不是对生产数据或鉴权正确性的证明。

只有候选断言决定通过；基线仅供对比。任一模型/工具异常导致 ERROR，不会伪造成通过。真实模型调用会产生费用；自动化测试使用脚本模型或受控接口响应，本轮未调用付费模型。

评测记录状态 RUNNING → PASSED / FAILED / ERROR，终态不可覆盖。单实例有界执行器一次运行一个任务，数据库全局并发限制为1；超过20分钟的运行任务标记 ERROR，进程重启后可读取历史结果，中断任务不会被视为通过。不做自动重试，以免重复费用；暂不引入分布式任务队列。

确定性服务端回归继续在既有 CI 执行。本轮没有新增 CI 构建证明上传/远端证明校验，候选门禁不能代替应用部署前的 CI 验收；历史 `eval-live-*` 报告仅供参考，不用于证明候选版通过。

## 数据库与部署

新增 `ai_prompt_control` 控制行和 `ai_prompt_evaluation` 快照表。幂等 DDL 同源写入 `db/schema.sql` 与 `db/migration/V12__prompt_evaluation.sql`，正常应用启动自动初始化；存量环境也可提前执行 V12。必须先准备新表，再使用新版草稿/发布接口。

本轮没有重启、停止或替换用户正在运行的后端实例，也没有发布任何真实提示词。旧接口调用者必须补齐 contentHash/evaluationId，不能沿用只传版本号的发布请求。

## 第二批：平台基础规则与业务补充分离（2026-10-22）

### 已实现的边界

- 人工审阅内置模板后，将原有48条行为约束和自检、工具/知识引用纪律完整冻结为 `prompts/platform-v1.st`，版本 `platform-v1`。这些都是平台行为规则；不按标题自动切割历史自定义正文。业务区初始为空，仅补充业务表达与工作习惯。
- 页面显示只读基础规则、业务补充编辑器、最终组合预览及与生效正文的差异；历史版本可“查看快照”。基础版本与基础哈希可核对，基础正文不由客户端提交。
- 新增 `GET /api/ai/config/prompts/base`（`ai:config:view`），返回 `version/content/contentHash`。保存草稿接口改收 `businessContent/note/baseVersion/baseHash/migrationSourceVersion/migrationSourceHash/migrationConfirmed`；业务文本允许空串，最多60000字符。服务端校验当前基础版本/哈希并生成最终正文与最终内容哈希，旧版仅传 `content` 的客户端须升级。
- 旧发布版继续按原文运行；旧完整草稿和发布版只有经过人工核对、勾选确认并提交匹配的来源版本/哈希后，才创建新的组合草稿。旧正文和内容哈希保留；来源变化拒绝迁移。迁移后的新版本发布时，不重新载入被其替代的旧草稿。
- 新草稿评测与发布先核对组合快照完整性。未迁移的旧草稿即使保留所有标题，也不能重新评测或发布；标题检查只用于旧历史版的兼容回滚，不能充当新版本的保护证明。
- `ai_prompt_composition` 持久化版本号、基础版本/哈希/正文、业务正文及迁移来源版本/哈希；`ai_prompt_version.content/content_hash` 仍是最终完整正文真源。保存正文与组合元数据在同一控制行锁及事务中；SQL也限定只有DRAFT可以更新组合快照。
- 评测使用最终完整正文，配置指纹额外绑定应用当前基础版本/哈希。发布校验持久化候选证据，审计追加基础版本/哈希及迁移依据；不记录正文。回滚使用目标版本原有完整正文与基础快照，既不按当前应用基础规则重组，也不重跑模型。
- V13与schema.sql同源、幂等新增组合表，不改写任何历史版本。启动初始化可自动建表；也可部署前先执行 `V13__prompt_composition.sql`。运行期仍保留原有内置兜底。

基础规则来自应用版本交付。未来调整必须使用新的基础版本号，管理员核对后保存新草稿、重新评测发布；不能重写已有 `platform-v1` 或在读取发布版时自动拼接新基础规则。业务补充与基础冲突时提示模型遵守基础规则；现有服务端权限和确认机制仍是真实执行边界。四道时间场景评测不证明任意业务补充都符合全部规则。

## 2026-10-22 配置变更历史修正

用户反馈时间不对且看不出修改内容。核对代码和数据库后确认：默认日期使用toISOString取UTC日期，在北京时间凌晨把结束日期设为前一天，从而筛掉当天新操作；例如2026-10-22凌晨只查到10-21旧记录。数据库当前审计时间正确，本轮未平移或重写历史时间。时间列现使用统一格式yyyy-MM-dd HH:mm:ss，去掉原始ISO的T，默认查询日显式按Asia/Shanghai计算。

变更列表改为中文前后值摘要（例如“模型温度：0.2 → 0.3”），主列优先展示修改内容。展开仍可查看字段详情；密钥引用只展示已变更、不展示敏感值。提示词新增“查看正文对比”，展示带行号的删除/新增片段及完整原文。

后端发布/回滚审计改为记录真正的原生效版本和目标版本（versionNo、source、contentHash、基础版本/哈希），after增加promptAction区分发布与回滚。此前记录的是目标自身DRAFT/ARCHIVED→PUBLISHED，不能据此推断原生效版；这类旧记录明确提示缺少切换前版本，仅在目标哈希一致时查看目标原文，不按时间或版本号猜测前版。内置模板也须哈希匹配才能用于对比；哈希不一致/版本不存在/无权限均显示无法还原，不用其他内容替代。
